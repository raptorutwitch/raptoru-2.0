## 4. Suite de la livraison (après la fusion)

`SHA` = le commit de fusion sur `main`, une fois sa CI verte. Dans un worktree à jour de `origin/main`, avec
`COOLIFY_URL=https://dashboard.raptoru.fr`, hors live :

1. Sauvegarde de la base (< 60 min) : Coolify › `raptoru-prod-postgres` › Backups › Backup now. Autre voie :
   `PATCH /api/v1/databases/4jaqdyvzlelgwkyvuxhjy4mr/backups/ha3t1pu8q83re2gjvg5wetbu {"backup_now":true}`.
2. `node scripts/coolify-deploy.mjs plan core SHA --migrations-approved` → PRÊT.
3. `node scripts/coolify-deploy.mjs deploy core SHA --migrations-approved --go`, puis vérifier `applied:
20261122130000_music_hub.sql`, `/health`, `/ready` et `status core`.
4. `node scripts/coolify-deploy.mjs plan bot SHA`, puis `deploy bot SHA --go`, puis `status bot` (bail actif).
5. Studio : Actions › « Studio — construire / publier ». D'abord `publish=none` (installateur et test de mise à jour),
   puis `publish=public`, version `0.1.28`, confirmation `PUBLISH studio <7 caractères de SHA>`.
6. Antoni installe 0.1.28 depuis Studio (« Rechercher une mise à jour »), hors live.
7. Extension : [extension/TWITCH_SUBMISSION_2026-11-10.md](extension/TWITCH_SUBMISSION_2026-11-10.md) § 4.

Consulted: 2026-11-07 (the session crossed midnight; a few fetches are timestamped 2026-11-08). All pages fetched live (raw HTML saved under `audit-ext/raw/`).

## 2. Contradictions / outdated / ambiguous points found

1. **318 × 496 vs Panel Height 100–500.** DES says panels "are limited to 318px wide x 496px high"; LC says Panel Height default 300, range 100–500. The 496 figure has no console/policy counterpart; it is a design-guide statement. Neither page states whether 318 is the inner iframe width or includes borders.
2. **Two CSPs on dev.twitch.tv.** GS (updated 2026-07-31 per CL) shows allowlist-based `connect-src`/`img-src`/`media-src`. LC "CSP for Reference" still shows `connect-src https: wss: …` and `img-src * data: blob:` / `media-src * data: blob:` — the permissive pre-2022 policy (CSP enforcement introduced 2021-09-30 / 2022-01-21 per CL). LC is outdated; GS is current.
3. **style-src host typo.** GS prose says style-src includes "https://fonts.google.com" while its example CSP says `https://fonts.googleapis.com`.
4. **onPositionChanged** was removed from the reference on 2026-06-08 ("unused"); old mirrors/forum posts still describe it.
5. **Component sizing** (aspect ratio, target height, autoscale/scale pixels) is no longer documented on dev.twitch.tv; only 2019 forum posts describe it.
6. **"Inline scripts without a nonce/hash"** (LC): the Twitch-generated CSP contains neither nonces nor hashes, so there is no documented way to supply one.
7. **Helper placement.** POL 2.9 "first script in all front-end HTML files" vs. GS's CRA example placing it in `<body>` and the hello-world placing it after content — both are compatible only if no other script precedes it.
8. **Review-channel live requirement.** POL 1.1 "All submitted review channels must be live during the time of review" vs. LC/SBP "you are not required to have your review channel live while waiting … Panel-only Extensions also do not require a continuously-live review channel."
9. **Extension PubSub.** BLD/REF still document `Twitch.ext.send/listen` and `wss://pubsub-edge.twitch.tv`; CL 2026-06-12 removed "The legacy PubSub migration guide". Not investigated further (outside scope).

## 3. Not confirmed from official sources

- Any fixed pixel size for the **mobile** viewport, the overlay, theatre or fullscreen.
- Any **browser-zoom** behaviour, minimum panel width in narrow windows, or how Twitch handles panel width below 318 px.
- Format of `displayResolution` / `videoResolution` strings (e.g. "1920x1080") — only "string".
- Any Helper API exposing the **iframe's own size**.
- A **zip file-size limit** (only mobile "should not exceed 1MB" initial load, and screenshot < 10 MB).
- The current names/defaults/limits of the **component** sizing fields in today's console.
- Minimum **font size** or WCAG level (only "enough contrast" + 44 pt/dp touch target for mobile).
- A formal rule against an overlay **covering player controls** (only design advice: controls render above the overlay; avoid the marked zones).
- Whether `allow-same-origin` storage (`localStorage`, cookies) survives in all browsers' third-party contexts — not documented.

# Tombola V2 — matrice de parité prototype → produit

Spécification : `prototypes/tombola-v2/` (validée par Antoni comme spécification produit / UX / DA ; local, non
versionné). Variantes retenues : overlay **C4** (ouverture), **G** (reveal normal / SUPER / giveaway), **roulette
compacte** (FULL OSEILLE), annulation, FIFO ; ancrage overlay **56 px haut / 56 px droite** pour toutes les phases.

Décisions d'Antoni (01/10/2026) : D1 registre de monnaies Lab générique · D2 simulateur de chat + ingestion
Twitch réelle derrière un interrupteur OFF · D3 cagnotte ~78 / 18 / 4 % · D4 gagnants auto · D5 phases Core,
reveal viewer = type + nombre de gagnants + marge · D6 SUPER 1/400 · D7 permissions (« Gérer la Tombola ») ·

variantes ni x1/x4 · D12 UI minimale pour participants / durées / fiche manche. Phase C : supermod = accès
complet (configuration comprise) ; pas de nouvelle manche pendant l'affichage d'un résultat ; ajout manuel
au-dessus d'une pause, jamais au-dessus d'un blocage individuel sans `force` audité. Ajout : planificateur
automatique + son de lancement (avant la phase D).

## Ingestion chat du Lab (générique, pas propre à la Tombola)

Une seule connexion Twitch pour tout le Lab (EventSub `channel.chat.message`, `stream.online`, `stream.offline`) :

- **Bot** `apps/twitch-bot/src/lab-chat-ingest.ts` (+ `lab-chat-main.ts`) : relaie sans décider. Chaque commande
  (`!…`) part vers `POST /v1/lab/chat`, l'état du stream vers `POST /v1/lab/stream` (env `LAB_CHAT_*`). Rien n'est
  écrit dans le chat. Scope requis : `user:read:chat`.
- **Core** `apps/core-api/src/lab-chat/router.ts` : chaque message est proposé à tous les modules Lab qui gèrent le
  chat ; chacun reconnaît ses commandes (ou répond `ignored`). Aujourd'hui : Tombola. Ajouter TTS (`!canceltts`),
  commandes globales, commandes de modération / test = ajouter un module à la liste dans
  `http/lab-moderation-routes.ts`. Jamais une deuxième connexion EventSub, un deuxième jeton ou un deuxième processus.
- **Studio** `apps/studio/server/src/lab-chat/ingress.ts` : un seul interrupteur (`.runtime/lab-chat/ingress.json`,
  OFF par défaut, jamais activé automatiquement), processus `labchat`, raison du blocage affichée telle quelle, et le
  simulateur de chat (`/api/lab-chat/simulate`) qui passe par la même entrée Core.
- **Pourquoi l'interrupteur ne s'activait pas (retour phase D)** : le clic était bien enregistré, mais la vue ne se
  redessinait pas (interrupteur affiché décoché) ; et le processus aurait de toute façon quitté aussitôt, le jeton du
  bot (`lecroupier_`) n'ayant que `moderator:read:chatters`, pas `user:read:chat`. Désormais l'interrupteur est
  verrouillé avec la raison et la marche à suivre (`npm run twitch:auth -w apps/twitch-bot`, accepter la lecture du
  chat).
